The person behind it

Hey, I'm Gurneil.

I'm in grade ten, in the IB programme at Turner Fenton in Brampton, and I'm in HOSA — the future health professionals club. Last year I competed in CPR and Basic Life Support at two leadership conferences. You learn the protocol properly: check, call, compress. Every step is written down because under pressure people skip things.

Then I started reading about AI scribes — tools that listen to a doctor's appointment and write the note afterwards. They're already being used on real patients. And the studies on them keep finding the same thing: the notes come out fluent, professional, and sometimes wrong. A dose that was never said. A "denies chest pain" turned into "reports chest pain." One word, and the chart now says something the patient didn't.

What got me was that nobody catches it by reading harder. A wrong note doesn't look wrong — that's the whole problem. So I built the thing that checks, instead of the thing that writes.

The project

What Clinical Note Guard
actually is

An ambient scribe records a visit and writes the clinical note. This is the layer that checks that note before a human signs it — not by re-reading it, but by taking it apart.

The problem

A wrong note reads exactly like a right one

That's what makes it dangerous. Asking a model to "check this note for errors" fails for the same reason a tired human does: nothing forces it to check every single claim, so it skims a paragraph that reads fine and moves on.

The idea

Decompose, then verify one fact at a time

The note is broken into atomic claims — one dose, one vital, one denial each. Every claim is checked against the transcript on its own, and has to come back supported, contradicted, or not mentioned, with a quote. You can't skim a checklist.

The mirror

And check what the note left out

Reading the note can only find things that are wrong in it, never things missing from it. So a separate step reads the transcript and asks whether each fact made it into the note — which is how a documented allergy that vanished gets caught.

The catch

The transcript is a model's output too

Everything above trusts the transcript. But if it came from speech recognition, it's an unverified model output — and this project is built on not trusting those. On degraded audio, Whisper invented an entire conversation and the checker passed all eight claims, correctly, because they matched the fiction it was given. So claims resting on audio the recogniser was unsure of now come back unverifiable, with a timestamp.

The rule

Nothing is ever corrected automatically

Every flag is a suggestion with its evidence attached, and a person confirms or dismisses it. The tool doesn't diagnose, doesn't recommend treatment, and doesn't edit a chart. It decides whether the note matches the transcript, and hands that to a human.

How I worked on it

Measured, including
when it lost

Three things in this project are results I didn't want, and they're the ones I'd point a judge at first.

01

A node that earns nothing

I re-scored the run with each node withheld. My deterministic dose checker contributed zero extra recall — everything it caught, the entailment step already had. It's in the docs, not buried.

02

A fix that didn't work

The obvious answer to my false-positive rate was ranking flags by severity. I built it, measured it, and it changed nothing — the real error was already first. So it isn't shipped.

03

A baseline I made stronger

The comparison prompt originally couldn't spot omissions, which would have handed me a free win. I told it to look for them. My lead survived, which is the only reason the comparison means anything.

All data is synthetic — sixty invented transcripts about fictional patients, written for this project. No real patient data is used or needed anywhere, and this is not a medical device.
