The problem

Built to catch wrong doses

An AI scribe writes a note that reads perfectly. One number is wrong, one denial is flipped, one allergy never made it in. A single-prompt "check this note" review skims past exactly those, because nothing forces it to check every claim. This pipeline does force it: it decomposes the note into atomic claims, verifies each one against the transcript independently, then hands a person a short list of what to look at.

Encounter transcript · source of truth

Doctor: Hi Mr. Alvarez, good to see you. How have you been feeling since we adjusted your blood pressure medication?

Patient: Pretty good, actually. No headaches or dizziness like before.

Doctor: That's great. Are you still taking the lisinopril 10 milligrams once a day?

Patient: Yes, every morning with breakfast.

Doctor: Any side effects, cough, swelling in your legs?

Patient: No, nothing like that.

Doctor: Let's check your blood pressure today… okay, it's reading 128 over 82. That's a nice improvement from last visit.

Patient: That's good to hear.

Doctor: I want you to keep taking the lisinopril at the same dose and come back in three months for a recheck.

Patient: Sounds good, thank you.

SPatient reports feeling well since blood pressure medication adjustment.
SDenies headaches, dizziness, cough, or leg swelling.
STaking lisinopril 20mg once daily each morning with breakfast.

The assumption underneath everything

The transcript is
a model output too

Every node above checks the note against the transcript. That was fine while the transcript was typed by hand. The moment it comes out of a speech recogniser, this system is grounding itself in the one thing it never verified.

What the recogniser heard

“Hi, this is Alpera. I'm here for the studio… I think I've got a big one… Are you still taking a little bit of a 10-year-old? … It's leading 178.83. It's a nice and beautiful from last week.”

The same encounter as the demo above, through a bad speakerphone. Whisper didn't fail loudly — it returned fluent, grammatical English describing a conversation that never happened.

What the pipeline said about it

8 claims checked. All 8 supported.

And it was right to. Every claim genuinely is entailed by the transcript it was given. The note faithfully represents a fiction. When the transcript is the thing that's wrong, a perfect score is exactly what a correct implementation produces — a hallucinated encounter, certified accurate, ready to sign.

Node 3b withdrew all 8, each with the seconds of audio to re-listen to.

The threshold that catches it was measured, not guessed. One recording, degraded in steps:

clean0.835 – 0.901dose + BP intact
mild0.801 – 0.869dose + BP intact
heavy0.362 – 0.369both lost — invented speech
severe0.313 – 0.671both lost

Everything that kept the clinical facts scored at least 0.801. Everything that destroyed them scored at most 0.369. The cutoff sits at 0.55, in the gap — and the script that measured it ships with the number it produced.

Against the obvious approach

The baseline is the naive version of this product: one prompt, transcript plus note, "point out any errors." Both systems ran on the same 51 planted errors and the same 6 clean controls.

Pipeline
Baseline

5.3LLM calls per note, against the baseline's 1. Decomposition is not free.
5.5×the baseline's tokens (~3,280 vs ~600). Measured from provider response metadata, never estimated.
1.7×the baseline's latency (~12.8s vs ~7.5s per note). Whether that trade is worth it depends on your note volume — this project doesn't answer that for you.

Does each node earn its place?

Every flag records which node raised it, so the same run can be re-scored with any node withheld — no re-run, no extra API spend. This is the pipeline marking its own homework in public.

Node 3 · entailment +45.1 pts 23 errors nothing else caught. Also 11 of the 15 false positives — the literalism cuts both ways.
Node 5 · omission +3.9 pts 2 errors nothing else caught, for 4 false positives. One of them wasn't even an omission — it was a medication attributed to the wrong person.
Node 4 · numeric regex +0.0 pts Caught nothing the entailment node hadn't already caught. It stays because it costs no model call and raised zero false positives — but on this benchmark it is not adding coverage, and saying otherwise would be a nicer story than the data supports.

Stated plainly

What this doesn't do

A QA tool that oversells itself is a patient-safety problem. So here is the other side of the table.

No clinical judgment

It doesn't diagnose, doesn't recommend treatment, and doesn't decide whether a note is correct. It decides whether the note matches the transcript, and hands that to a person.

Decomposition costs precision

Seven atomic claims mean seven chances for a false alarm instead of one. On a clean note the pipeline raised 7 flags where the baseline raised 2. That is a real trade, not a rounding error.

The exact checker is narrow

Node 4 recognises mg/mcg doses and blood-pressure pairs. Units outside that set fall back to the LLM entailment check, with the ambiguity that implies.

The scoring here is a proxy

Reported numbers come from the automated scorer. A blinded human grading pass on the same committed outputs is the next step, and the blind scorecard is in the repo so anyone can run it.

Synthetic data only

Sixty invented transcripts about fictional patients, written for this project. No real patient data is used, needed, or stored anywhere.

Sample size is small

Sixty cases is enough to compare two systems on the same benchmark. It isn't enough to publish a clinical claim, and this project doesn't make one.
