Branch off node 2 · not a numbered node
Batching guard
Deterministic

Nodes 3, 5 and 6 each send one call per case, not one per claim, and the prompt demands exactly N objects in the same order. The returned array is length-checked against the claim list before anything is scored.

A per-claim loop would multiply cost by the claim count and let a silent re-ordering misattribute every verdict.

Transcript confidence
Deterministic

Plain Python, no model call. Joins each verdict to the audio segment it rested on.

seg_confidence < threshold → UNVERIFIABLE + timestamp

A claim checked against audio the recogniser was unsure of is not "supported" — it is unverifiable, and the reviewer gets a timestamp to re-listen to. Threshold calibrated by experiment, not guessed: eval/asr_confidence_check.py.

Not a numbered node · the comparison point
Single-prompt baseline
Baseline

The same transcript and the same note, handed to one call on CORE_REASONING_CHAIN — the same tier as node 3, the same case, always. No decomposition, no forced per-claim coverage, no taxonomy.

Query — verbatim
"review this note against the transcript and identify any documentation errors — both unsupported content AND anything relevant the note leaves out"

Output: a raw issue list, no forced structure, scored against the same ground truth by the same blind grader.

The "AND anything relevant the note leaves out" clause was added mid-project. The earlier prompt asked only for commission errors while being scored on omission cases node 5 had a dedicated node for — part of the original gap was an unfair prompt, not the design. It was fixed and re-run.

Methodology note — why the baseline shares a model

Node 3 and the baseline are pinned to the same chain, on the same case, always. Without that link, any measured gap could be the pipeline quietly running on a better model, and the result would be worth nothing.

The stronger-model check went against the design, and is reported anyway.

Pinning llama-3.3-70b-versatile as the fairness-critical tier puts the two level: over the 44 planted-error cases that completed in both runs, pipeline 39/44 either way, baseline 33/44 on the small model and 40/44 on the large one. Decomposition compensates for a weak reasoner rather than adding capability on top of a strong one.

Auto-scored, 44 of 60 cases; ten lost to Groq rate limits. eval/runs/README.md, ARCHITECTURE.md "The stronger-model check".
